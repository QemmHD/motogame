# v1.8.1 — Fast Failure, Great Finish

Release-candidate date: **2026-07-14**

Moto Rush X3 v1.8.1 completes the local implementation pass for U06 **Fast Failure, Great Finish**. The new code-native **Finish Forge** turns an authoritative finish into a compact run receipt: gross clock, flip credit, net time, itemized score, stars, personal-best comparison, replay proof, and a guarded next route share one responsive screen. Retry, Replay, Next, Menu, and Gold Run are now explicit focusable actions instead of an ambiguous tap-to-dismiss overlay.

This is an **unmerged local release candidate**, not a claim about the public Pages build. The active branch is `agent/motorush-v181-fast-failure`; its final commit, draft pull request, hosted Actions run, eligible publish, and production cache/install/offline smoke must be recorded after they exist.

## Player-visible update

### Finish Forge run receipt

The finish screen is now an original steel-and-signal Canvas composition designed for Moto Rush X3 rather than a generic modal. It includes:

- the course name, run number, gross clock, flip credit, and canonically rounded net time;
- a score receipt grouped into **TRICK BANK**, **AIR & LAND**, **RISK LINE**, and a safe fallback bucket;
- three physical star rivets with a short ceremony, or an immediately complete static state under Reduced Motion;
- time and score personal-best deltas, including tied-record handling;
- proof availability and next-route status in the same visual hierarchy;
- large Retry, Replay, Next, Menu, and Gold Run controls with a visible focus rail.

The itemized receipt does not recompute gameplay rewards. `run-session.js` remains authoritative for elapsed time, flip credit, finish time, score, and stars; `finish-flow.js` only validates and presents those values. Every recorded score event must reconcile exactly with the authoritative total or the report fails instead of silently displaying a different number.

### Exact time and personal-best behavior

Time comparisons now use canonical integer milliseconds. That keeps storage, presentation, and record decisions aligned and prevents sub-millisecond floating-point noise from creating a visible zero-millisecond personal best. The formatter carries rounding through minute boundaries, so `59.995` seconds displays as `1:00.00` rather than an invalid `0:60.00`.

A finish report rejects disagreement between the authoritative net time and gross time minus flip credit. Development, Gold, and replay playback remain ineligible to mutate live progression records.

### Safe result routes

Every result action is resolved by a DOM-free policy before browser state can change:

| Action | Contract |
|---|---|
| Retry | Starts the current course as a fresh live run. |
| Replay | Remains visible but disabled when a compatible player proof is missing; a stale runtime request fails safely. |
| Next | Appears only when the immediate next catalog entry exists, is playable, and is unlocked. It never clamps to the final course or skips a missing/locked entry. |
| Menu | Always provides a safe exit from results. |
| Gold Run | Appears only when the repository reference for the current course is available. |

The final course reports campaign completion instead of manufacturing another target. Missing current/next catalog records, malformed progression counts, and unknown actions fail closed without corrupting the save or starting the wrong course.

### Keyboard, touch, gamepad, and assistive technology

Finish Forge supports the same result flow across input families:

- Arrow keys or WASD move the visible focus; Tab follows the semantic button order.
- Enter or Space confirms; Escape or gamepad B returns to Menu.
- Standard gamepad D-pad/stick navigation and A confirmation use rising edges with press/release hysteresis, so a held direction does not repeat and a held gameplay throttle cannot dismiss a newly opened receipt.
- Pointer/touch activates only the registered button hit rectangle. Every enabled target is at least 44 × 44 CSS pixels, remains inside the viewport, and does not overlap at the 320 × 568 minimum layout.
- A real hidden semantic dialog mirrors the Canvas receipt and buttons, exposes disabled Replay state, announces the result through a live region, and restores the neutral game label after leaving results.

The document now declares English, the Canvas has an application role and keyboard focus, and the viewport no longer blocks browser zoom. Reduced Motion skips confetti and finishes the star reveal immediately while preserving every result and action.

### Reset ownership

Starting Retry, Next, Replay, Gold Run, or Menu clears finish focus, timers, semantic controls, live announcements, pooled effects, tracks, camera transients, crash/ragdoll/contact state, pending restart state, and UI-input latches. Audio reset cancels scheduled cues and active synthesized effect sources so a finish ceremony cannot leak into the next run. Save fields are normalized on load, while the existing save key and field meanings remain compatible.

## DOM-free policy modules

`public/finish-flow.js` owns detached result policy:

- score-ledger creation, reset, event bucketing, snapshot, and exact reconciliation;
- canonical time conversion, formatting, finish arithmetic, and PB deltas;
- playable/unlocked next-route resolution;
- result action construction, focus initialization/wrap, and mutation-free action resolution.

`public/ui-input.js` owns standard menu-direction, confirm, and back edges for browser gamepads plus keyboard command mapping. It is separate from `input-state.js`: ride commands remain fixed-tick authority, while UI commands are presentation edges sampled once per rendered frame.

Both modules have no DOM dependency and are part of the literal offline precache.

## Originality boundary

Finish Forge uses broad racing-game conventions—finish timing, score receipts, stars, personal bests, retry, replay, and next-course actions—but no proprietary competitor code, models, art, UI layout, copy, sounds, levels, or tuned data. Its forged-steel receipt, terminology, information hierarchy, focus rail, responsive composition, policy modules, and test contracts are authored for Moto Rush X3.
