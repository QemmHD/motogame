# v1.7.0 — Vector Weave

Release-candidate date: **2026-07-13**

Moto Rush X3 v1.7 turns the collision foundation into a new player-facing mechanic. **Kinetic Looms** are original, non-solid machine fields that weave a readable acceleration path through the course. The new R&D Yard route **Vector Weave** introduces three Loom roles in forgiving terrain, bringing the authored catalog to 16 routes.

This file records a tested local candidate, not a production deployment. The focused and cumulative gates, compatible Gold refresh, and four browser captures below are recorded from real outputs. Physical-device smoke plus production Pages/cache/install/offline checks remain required before promotion.

## Vector Weave

Vector Weave is the fourth R&D Yard route and the sixteenth authored route overall. It teaches one field role at a time before combining the mechanic with shaped terrain and a recovery deck:

| Loom | Field size | Authoritative acceleration | Teaching purpose |
|---|---:|---:|---|
| **Flow Assist** | 250 × 110 | `x +480`, `y 0` | A wide horizontal field demonstrates forward acceleration without changing the route's basic line. |
| **Loft Line** | 180 × 120 | `x +170`, `y -820` | An upward-forward field teaches controlled lift toward a visible sky deck. Positive world `y` points down, so the negative `y` value lifts the bike. |
| **Soft Landing** | 220 × 150 | `x +60`, `y -360` | A gentler upward correction helps shape the approach into a dip without becoming an invisible solid surface. |

Checkpoints divide the lesson into recoverable sections. The course retains ordinary terrain, a static one-way deck, whoops, and a conventional finish so the new field remains the focus rather than being hidden inside a dense gauntlet. Star targets are candidate authoring values until human keyboard and touch rides validate their fairness.

## Stateless Kinetic Loom contract

A Kinetic Loom is an immutable axis-aligned rectangle with a stable ID, center, dimensions, exact bounds, linear acceleration, angular acceleration, enable flag, and detached render strings. It has no timer, occupancy table, cooldown, switch memory, or checkpoint payload. Previous/current bike geometry determines overlap, swept entry, exit, and hit-node metadata afresh each fixed step, using exact circle-to-rectangle distance at corners rather than a false-positive-prone square expansion.

The authoritative order is deliberate:

1. Advance kinematic platforms.
2. Solve the bike against terrain.
3. Activate and resolve one-way platform contact.
4. Process scoring and advance rules/hazards.
5. If rules did not crash or finish the run and the bike is above fallout, evaluate enabled Looms.
6. Apply each field's `acceleration × dt` and `angularAcceleration × dt` through the bounded physics impulse API.
7. Capture a checkpoint or enter finish/crash/fallout lifecycle state.

The field impulse is written after the current bike solve and begins affecting motion on the next fixed physics tick. A same-tick lethal hazard or valid finish wins before a Loom can alter the ended run. Full restart recreates the immutable field, while checkpoint retry needs no Loom snapshot and deterministically derives entry/sweep results from restored bike geometry.

## Original visual language

Kinetic Looms use an original Moto Rush X3 identity: translucent woven ribbons, repeated directional chevrons, compact steel loom heads, route-specific labels, a **VECTOR LOCK!** entry callout, and a short synthesized cue. The reduced-motion setting freezes ribbon phase while preserving field bounds and direction. The full volume is deliberately drawn as light rather than a solid block so players do not mistake it for platform collision.

This work uses no competitor code, art, audio, course geometry, names, UI layouts, or extracted assets. It draws only on the broad genre idea that a stunt course can contain directional environmental forces. The Kinetic Loom name, rules, geometry, course arrangement, machinery, labels, palettes, feedback, and implementation are authored for Moto Rush X3.

## Collision-debug proof surface

The development collision overlay now includes every normalized Loom rectangle and a center-origin acceleration arrow clipped to that rectangle. Its detached proxy schema is:

```text
forceZones[] = {
  id, active, kind,
  bounds: { left, right, top, bottom },
  center: { x, y },
  acceleration: { x, y }, angularAcceleration,
  arrow: { x1, y1, x2, y2 },
  render: { ...bounded strings }
}
```

`limits.maxForceZones` bounds output, `truncated.forceZones` reports omitted definitions, and proxy construction does not run collision queries or mutate authoritative data. The visible Loom volume, normalized rectangle, and debug rectangle must agree in the final debug capture.
